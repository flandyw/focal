# AI chat

Sign in and add your Vercel AI Gateway API key under **Settings → AI**, then open **Chat** and pick a model from the searchable selector. The assistant can read your synced exams, mistakes, timetable, goals, and study history, and it uses the same validated tools as the MCP server when you ask it to make changes. You'll see each tool call and result right in the thread. Hitting Stop cancels the reply, though any write already in flight may still finish, so check your records before retrying. Local unsynced edits and historical desktop-only sessions aren't visible to the assistant, and chats live only in memory (they clear when you leave the page or switch accounts).

Make sure `supabase/migrations/0032_ai_gateway_vault.sql` is applied before saving keys. Keys are stored encrypted in [Supabase Vault](https://supabase.com/docs/guides/database/vault), separate from the sync feed and exported app data. Signed-in students can check whether a key is saved, replace it, or remove it, but can never read the plaintext key back. Only the chat server's service role can fetch a key, and only after verifying the caller's Supabase session. Deleting an account deletes its Vault secret too. Settings clears the input box as soon as you save and never shows the saved key again. Keys are never kept in browser storage or logged by the chat handler. Use HTTPS in production (localhost HTTP is allowed during local development); chat no longer accepts keys in request headers.

The model picker loads Vercel's public catalog and filters to language models that support tool use, and the server checks every selection against that list. `AI_GATEWAY_MODEL` sets the default model (`openai/gpt-6-luna`), while anything you pick applies to your current chat session. The server needs `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` to read from Vault. Study-data tools still run under the student's own session and row-level security. Keep the service-role key strictly on the server, and never put it or a Gateway key into a `VITE_` variable. Focal doesn't use a shared host Gateway key or OIDC fallback.

`bun run dev` and `bun run dev:desktop` serve `/api/chat` locally. Production web uses the Vercel function in `api/chat.ts`, or the same handler via `bun run start`. Packaged desktop builds need `VITE_CHAT_API_URL=https://your-focal-host/api/chat` at build time. The hosted endpoint allows Tauri origins and authenticates every request. Deploy from the repository root so the function has access to the `public` reference datasets.

Requests allow up to 60 messages (256 KiB), run at most six tool/model steps, and time out after 55 seconds. Rate limiting allows ten requests per user per minute per server instance (add a shared limiter if you need a strict cluster-wide cap). Billing and model access follow the user's own Gateway key and Vercel team settings. See [Gateway setup](https://vercel.com/docs/ai-gateway/getting-started) and the [shadcn chat components](https://ui.shadcn.com/docs/ai-elements/base/chat).

ChatGPT analysis features are desktop-only and run through the local sidecar; Gateway chat works on both web and desktop.
